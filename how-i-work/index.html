How I work with AI

AI agents are fast at producing code and unreliable at judging it. So I built a workflow where the agents do the implementation and every decision that matters goes through me: what we build, how it's designed, how we'll know it works, and what gets merged.

In one lineClaude writes, Codex reviews, I decide.

The tools

  • Claude Code (Anthropic) is the main agent: it plans, writes code and tests, and runs the checks. Smaller, cheaper models handle searching and routine sub-tasks.
  • Codex CLI (OpenAI) is a second opinion from a different provider. On high-risk work it critiques the spec, the plan and the final diff, read-only.
  • Zed is where I read and review the code.
  • GitHub holds every change as a small pull request.

All of it lives in one versioned repository. The files are the live setup: change one and the next session behaves differently.

  1. Classify it out loud. A one-line fix, a routine feature and a change touching login, money or personal data each get a different amount of process.
  2. Plan, then wait for my "go". The plan states what's in, what's out, how we'll know it works, and every assumption as a question. No code before I approve it.
  3. Tests first. A failing test, then the code that makes it pass.
  4. Review in proportion to risk. Routine work gets an automated code review. Risky work also gets a security threat model, a written spec and Codex's critique.
  5. Prove it. "Done" means real test output, not a claim that it passed.
  6. One small PR per concern, each in its own isolated copy of the repository, so parallel sessions never collide.

What's automatic and what's mine

Much of the know-how is packaged as skills: instructions the agent loads for a specific job, like a security audit, a UI review or test-driven development.

The AI follows written instructions most of the time, not always. So the rules that matter are enforced by hooks, small scripts that can block an action: no edits on the main branch, no commit while tests are red, no ending a session while a security audit is owed.

What stays mine: approving plans, product and taste calls, anything touching security or privacy, and the final merge. When in doubt, the agent stops and asks.

Principles

  • Plan before code. Most of the alignment with the AI happens at the plan, not the diff.
  • Small diffs. A change too big to review properly doesn't get merged.
  • Security is never skipped for looking small.
  • Two providers, not one. The model that wrote the code doesn't get the last word on it.
  • Measure the setup itself. I audit token cost and time from real sessions and drop the process that doesn't pay for itself.
